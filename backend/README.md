# Auto Sale Umar unified backend — clean account bootstrap

This is a first-stage migration patch, not a production deployment. Do not use an old D1 ID. No catalog, accounts, sessions or R2 objects are copied. The baseline was reconstructed from the shipped API code because original migrations 0001/0002 were absent. Existing migrations 0003–0009 follow it. The web, native client and TV use one Worker; legacy Pages handler modules are imported in-process, not separately deployed. The new app catalog uses api.autosaleumar.com/v1/cars; same-origin /api endpoints are kept for web and native admin compatibility.

1. New Cloudflare account: create D1 `autosaleumar-db` and R2 `autosaleumar-media`. R2 must be enabled. In web GitHub repo set secrets `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` (new account only, Workers scripts, D1, R2 and zone/route permissions as needed), `AUTH_PEPPER`, `SETUP_KEY` (fresh random >=32 characters each), optional `GEMINI_API_KEY`; variable `ASU_D1_DATABASE_ID` = new DB UUID. Do not rotate AUTH_PEPPER after creating accounts unless intentionally resetting authentication.
2. Upload patch using existing installer. Add supplied `deploy-autosaleumar-backend.yml` manually at `.github/workflows/deploy-autosaleumar-backend.yml` after patch succeeds (the installer protects workflows). Run manually with attach_domains=false. Inspect workers.dev URL in deployment output, verify `/v1/health`, `/api/catalog`, `/v1/cars` and empty catalog. Register first super-admin at `/admin/setup/` on staging; use the new setup key. Confirm login, staff roles, create a test car, upload media, edit and publish, then remove test data manually before opening business. Never reuse old keys. Protect setup/login and public submission endpoints with rate limits at Cloudflare; setup endpoint refuses additional users.
3. Add autosaleumar.com zone to new Cloudflare account, preserve necessary non-app DNS records (MX/TXT, verification etc.), disable old DNSSEC before moving if enabled. In Spaceship replace nameservers with two nameservers assigned to the NEW zone. Wait for Active, then run deploy with attach_domains=true. Verify TLS and all URLs. Do not delete old resources until validation is complete. Old Pages project does not need to be connected in the new account.
4. New Apple account: register explicit `com.autosaleumar.showroom` (proposed; check availability), create new App Store Connect record, new signing identity and profile, new app credentials. Use app ZIP and manually replace app workflow `testflight.yml` and legacy `deploy-app-api.yml`. Disable obsolete `prepare-signing.yml` which uses old iumrah signing. New TestFlight workflow checks team + profile + cert/private key match; configure the two hash variables using the newly generated artifacts, not old ones.

Validation: SQLite applied all migrations to empty DB; 116 static SQL statements compiled; both catalog base SELECT queries returned no rows. TypeScript transpile syntax and Swift syntax checked. Full Next.js build unavailable due npm dependencies not cached / network timeout; iOS SDK unavailable; real Cloudflare deploy, login/media test and Samsung testing still required. Remote control, reveal gallery, Sale Pending and music are a separate next phase. Wake Lock and the new opening sequence are included in this patch.
